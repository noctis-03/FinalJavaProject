# 4.2 프로젝트 회고

---

## 잘 된 점 (1/2)

- **단방향 레이어 구조 유지**
  View → Controller → Service → DAO → DB 의 단방향 흐름을 일관되게 유지했다. 한 화면을 수정해도 다른 화면이 망가지지 않는 구조가 끝까지 유지되었다.

- **블록 추상화를 통한 확장성 달성 (NFR-024)**
  텍스트·링크·파일·자동화 블록을 동일한 방식으로 다룰 수 있어 기능 추가가 용이했다.

- **그래프형 자동화 UI**
  자동화 블록을 단순 리스트가 아닌 캔버스 위 노드로 구현하고, 출력 포트를 드래그해 파일·링크에 연결하는 방식으로 직관성을 크게 높였다.

---

## 잘 된 점 (2/2)

- **미리블록 템플릿**
  자주 쓰는 일정을 템플릿으로 저장해두고 캘린더에 끌어다 배치하는 기능이 잘 구현되었다.

- **과제-캘린더 자동 연동**
  과제 생성 시 캘린더에 마감 표시가 자동 생성되고, 과제 삭제·마감일 수정 시에도 캘린더 표시가 즉시 반영되어 두 화면이 어긋날 일이 없다.

- **일정 충돌 검사**
  일정 추가 시 항상 동일한 충돌 검사 로직을 거치며, 충돌 발생 시 대상 일정 이름까지 함께 안내되어 안전하다.

---

## 아쉬운 점 / 개선 사항

- **파일 경로의 로컬 의존성**
  파일 등록 시 로컬 절대 경로가 저장된다. 실제 파일을 클라우드나 서버에 올려두고 어디서든 열 수 있는 형태로 개선할 수 있다.

- **블록 종류의 제한**
  현재 사용자가 활용할 수 있는 블록의 종류가 많지 않다. 향후 업데이트를 통해 블록 유형을 추가해 나가야 한다.

- **LMS API 미지원**
  HI-CLASS, 헤이영 등 학교 LMS의 공개 API가 존재하지 않아 시간표 자동 불러오기 기능 구현에 어려움이 있었다.
