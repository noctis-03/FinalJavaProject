## <4.2 프로젝트 회고>

### 잘 된 점
- View → Controller → Service → DAO → DB 의 단방향 흐름을 일관되게 유지했다
- 한 화면을 손봐도 다른 화면이 망가지지 않는 구조가 끝까지 유지된 점이 좋았다.
- 블록 추상화를 통한 확장성 (NFR-024 달성)으로 텍스트·링크·파일·자동화 블록을 동일한 방식으로 다룰 수 있었다.
- 자동화 블록을 단순 리스트가 아니라 캔버스 위 노드로 만들고, 출력 포트를 드래그해 파일·링크에 연결하는 그래프형 UI로 풀어낸 점. 직관성이 크게 올라갔다.
- 자주 쓰는 일정을 템플릿으로 만들어두고 캘린더에 끌어다 사용 하는 기능이 잘 구현 된 것 같다. 
- 과제를 만들면 캘린더에 마감 표시가 자동으로 생기고, 과제를 지우면 그 마감 표시도 함께 사라진다. 마감일을 수정하면 캘린더 표시도 자동 업데이트되어 두 화면이 어긋날 일이 없다.
- 특정 상황을 제외하고 일정을 추가할 때 모두 같은 충돌 검사 로직을 거쳐 겹치는 경우 충돌 대상 이름까지 함께 안내되어 안전하다. 

<br>

### 아쉬운 점 / 개선 사항
- 파일 등록을 하면 로컬 절대 경로가 저장된다. 실제 파일을 클라우드나 서버에 올려놓고 어디서든 여는 형태로 개선할 수 있다.  
- 사용자가 사용할 수 있는 블럭의 종류가 많지는 않다. 앞으로의 업데이트를 통해 추가해 나가야할 부분이다. 
- HI class나 헤이영 등 APi의 활용으로 시간표 자동 추가 기능이 있으면 편리할 것 같다. 하지만 현재 따로 API가 존재하지 않아 (사용할 수 없어)
기능 구현에 어려움이 있었다.
